1. Scope and method

  • Automated layer. The full solution build, the five backend suites (domain, architecture gates, application, integration on a real PostgreSQL, functional through the real API), the frontend lint with module boundaries, the frontend unit tests and the production build.
  • Manual layer. Three testers covered the Release-1 menu of both portals and the public pages. They tested every list, editor, row action, dialog, permission of each persona, and the Arabic right-to-left view. Each tester worked on a separate host name (127.0.0.1 or localhost), so their sessions never mixed. Expected results came from the business SRS (LIS-SRS-001), the module intakes and the UAT scripts.
  • Pinned build. During the run, another working session changed the registration page and released it as v0.5.0. The browser site was then switched from the hot-reloading development server to a pinned copy of the v0.5.0 build (tests/validation/serve-ui.mjs), so later edits could not reach the code under test. The Super Admin tester finished on the development server. Its pages are identical in v0.4.1 and v0.5.0, because v0.5.0 changed only the registration page. The client operations tester re-ran the whole registration page on the pinned build.
  • Backend cycle. After every save the testers queried the database read-only. The script tests/validation/backend-cycle.mjs drove a full laboratory cycle through the API with database assertions, on the validation API and on the installed site.
  • Release-1 scope only. Release-2 pages hidden by the release switch were tested only for being refused.

Observations fixed with the defects

  • O-9 (set-up): a technician without billing rights saw the day's collected cash on the dashboard. The amount is now sent and shown only to users with the billing right.
  • O-1 (set-up): activating a price list now asks for confirmation; it changes what cash patients pay.
  • Search with "_" or "%": found during the fixes. Several searches found nothing for a typed underscore or percent sign, because the database was told to use no escape character. Every search now passes it, and an architecture gate refuses the faulty form.
  • Plural wording: Results says "1 result saved" instead of "1 results saved".

6. Points for the business owner

These are not defects of the build. Each needs a decision or a data check before go-live.

  • VIP masking (A-03). The PAT and REG intakes disagreed. The stricter rule was applied (see the register) and both intakes mark it as an assumption. Please confirm. The results worklist still shows VIP names, because it was outside the decision.
  • eGFR formula. The demo catalogue computes eGFR without the age and sex factors of MDRD. This is catalogue data; check the formula of the real catalogue.
  • Biohazard mark. Sample labels carry the urgent mark but no biohazard mark for a biohazard visit.
  • Failed attempts. A wrong current password in "change password" counts toward lock-out. The security spec should say whether it must.
  • Normal and Critical on one list value are both allowed (O-2).
  • Test-level duplicates (O-3). A test inside a profile inside a package can be ordered again as its own service. Confirm whether "refuses duplicates" means services only.
  • Treasury access across branches (O-4). The request picker offers treasuries of branches the user is not assigned to.
  • Trail events for edits (O-5). Payer, tier, treasury and price-list name edits write field changes but no trail event.
  • Release-2 modules in the privilege matrix (O-7) can be granted, and the clinical group's "Report template" field has no option (O-8).
  • Shared device id (O-10). Treasury approvals follow the browser profile, not the person.
  • Known open points carried from the remaining-points list: no decision reason on treasury-access rows (D-05), the Egypt mobile rule of 10 digits without the trunk 0, and the SMS and e-mail gateway that blocks three cases.

Changes worth knowing

  • Sessions. Tabs take turns to refresh, and the server accepts the token it has just rotated for 5 seconds (Lis:Security:Session:RefreshReuseGrace). A replay after that still revokes the session and raises the alarm. A forced password change is enforced by the server (AUTH-016). The cookie of a session ended by sign-out is refused without a false alarm.
  • Lists. Every paged list sorts on the server before paging, from an allow-list of columns, case-insensitively. Every text search treats "_" and "%" literally; an architecture gate enforces it.
  • Data. One migration, GrantExportPermissions, is data only. One new tenant parameter, timeZone. New endpoint GET /api/v1/patients/conditions.
  • Minor observations left. The unknown-zone message is generic, though it shows on the right field. Full-page editors mark the fields of a blocked save but show no notice. "1 tube(s) were issued." still reads in the plural form. Results by accession keeps Latin digits in its dates, as on the printed reports; the business owner may choose one digit rule.
