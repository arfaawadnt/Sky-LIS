# Release-1 UAT — automated dry run · Operations Admin, Master Data Reviewer, Super Admin

Scripts: LIS-UAT-001 v0.3 (`docs/uat/Release-1_UAT_Scripts.md`), corrected to v0.4 by this run. Build: `VERSION` 0.3.4
(commit `5934e78`) plus the uncommitted fixes listed in §4, on the development servers (SPA 127.0.0.1:4300, API 5100,
database `lis` on the private PostgreSQL 5433). Tester: **automated dry run** (browser automation driving the Super
Admin portal and, for the isolation and copy checks, the client portal; data entered through the pages only). Date:
2026-10-10. Only the **critical** scripts of the three personas were executed, in the order Operations Admin → Master
Data Reviewer → Super Admin requested for this run. It continues the two earlier dry runs
(`2026-10-10_dry-run_admin-reception.md`, `2026-10-10_dry-run_laboratory.md`): same conventions, their data reused,
defect numbering continued after D-11.

Deviations from a human session, all recorded below where they matter:

- The run order puts UAT-OPS and UAT-MDR before UAT-SUP-01/02, which create their personas: the OPS and MDR scripts
  were therefore executed as **`platform.admin`** (every permission). After UAT-SUP-02 the real personas were used
  where a script needs them: `uat.ops` re-ran UAT-OPS-01 steps 1–3 and UAT-SUP-08 step 4; `uat.mdr` signed in for
  UAT-SUP-02 step 3.
- Mouse clicks landed only while the Browser pane was at its own size; with the pane shrunk (349 × 265 px) or an
  emulated viewport every click was dispatched on the page's own buttons and inputs from the page context
  (`element.click()`, `input` / `change` events), which runs the same Angular handlers as a user's click. Values were
  entered with `form_input` or the same page-context events. Screenshots were not usable.
- **Forced requests were not executed** (the bearer token lives in a signal; a page-context `fetch` answers
  `AUTH-001`). Every "forced request answers `XXX-nnn`" expectation is recorded as *not executed*; the page-level
  refusal is what the sheet reports, and the backend suites keep the codes covered.
- One browser profile: "a session already open elsewhere acts" (UAT-OPS-03 step 2) could not be observed; the
  sign-in refusal after the deactivation was.
- Data minimisation: two laboratories (UAT Lab B, UAT Lab C), one plan (UATPLAN), the global catalogue items UAT-MDR-01
  needs (CHEM, SER, mIU/L, TSH, service TSH), the two platform roles and three platform users of UAT-SUP-01/02, and one
  throw-away laboratory user (`uat.short`, UAT-SUP-05 step 2). Nothing of the earlier runs was deactivated or deleted;
  UAT Lab B and the plan UATPLAN were deactivated and reactivated by their scripts. The platform parameters were
  restored (minimum password length 8, trial days 14).
- No notification gateway on the development lane: UAT-OPS-07 (*gateway*) and UAT-SUP-05 step 3 (trial end of a
  wizard client) are blocked.

## 6. Open points for the business owner (added to LIS-UAT-001 §9 as 11–13)

1. Where the creation of a client is audited: today the new laboratory's trail (and the security-event ledger), not
   the platform trail (D-15).
2. Client-page URLs are reachable from a platform session until the client feature routes carry the `tenantGuard`
   (D-17; the server scopes every call to the platform tenant).
3. Route-provided facades keep their data across visits and sign-ins; the platform, organization and catalogue features
   now re-read on open (D-14), the laboratory features (registration, patients, results, pricing, treasury, …) still
   follow the old pattern.
4. The global catalogue of a fresh platform is empty: the copy to a new client (BR-25) is only as rich as what National
   Technology entered before the client was created (OQ-03 confirmed: later changes do not reach existing clients).
