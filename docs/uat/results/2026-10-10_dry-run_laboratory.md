# Release-1 UAT — automated dry run · Cashier, Accounts, Phlebotomist / technician, Laboratory technician, Unit head

Scripts: LIS-UAT-001 v0.2 (`docs/uat/Release-1_UAT_Scripts.md`), corrected to v0.3 by this run. Build: `VERSION` 0.3.3
(commit `548f224`) plus the uncommitted fixes listed in §3, on the development servers (SPA 127.0.0.1:4300, API 5100,
database `lis` on the private PostgreSQL 5433). Tester: **automated dry run** (browser automation driving the client
portal; data entered through the pages only). Date: 2026-10-10. Only the **critical** scripts of the five personas were
executed, in the order Cashier → Accounts → Samples → Results → Verification requested for this run (the document's
run order puts the Accounts scripts first; FIN-02 was therefore executed before the registrations that need CREA and
BLDGRP prices, see §4). It continues the first dry run (`2026-10-10_dry-run_admin-reception.md`): same conventions,
its data reused, defect numbering continued after D-07.

Deviations from a human session, all recorded below where they matter:

- The Browser pane of the automation stayed hidden (a 320 × 241 px document, `visibilityState` hidden): mouse clicks
  did not reach the page, so every click was dispatched on the page's own buttons and inputs from the page context
  (`element.click()`, `input` / `change` events), which runs the same Angular handlers as a user's click. Native print
  windows (receipts, labels, reports) could not be inspected; "sent to the printer" toasts and the status logs are the
  evidence. Screenshots were not usable.
- **Forced requests were not executed.** The automation's safety classifier refused to place a bearer token into the
  page, so every "forced request answers `XXX-nnn`" step is recorded as *not executed*; the page-level refusal is what
  the sheet reports. The backend tests of the modules keep those codes covered.
- One browser profile: the "cashier's own profile" was emulated by sign-out / sign-in cycles on the same device id
  (`a0ab790c-…`), which is exactly what revealed D-08.
- Data minimisation: the four UAT roles and users the executed scripts need were created as `lab.admin` through Setup
  (Cashier / `uat.cashier`, Accounts / `uat.accounts`, Unit head / `uat.head`, Technician (chemistry) / `uat.tech.chem`)
  plus the HAEM library comment of UAT-ADM-10 (precondition of RES-04) and the reportable low of CREA (RES-02 step 4).
  `uat.cashier` was created with *Must change the password* left ticked by mistake (a tester's slip, not a defect) and
  changed its password at the first sign-in, which incidentally re-ran UAT-ADM-03 steps 6–7 for the cashier.
- The automation ticked role checkboxes in one burst on the first attempt; only the last tick survived (the privilege
  matrix recomputes from its input between change-detection cycles, which a human never outruns). The roles were
  corrected with paced clicks before any script ran; nothing of that is a product defect.
