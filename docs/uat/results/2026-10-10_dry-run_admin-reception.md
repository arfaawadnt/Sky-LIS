# Release-1 UAT — automated dry run · Laboratory administrator and Reception clerk

Scripts: LIS-UAT-001 v0.1 (`docs/uat/Release-1_UAT_Scripts.md`), corrected to v0.2 by this run. Build: `VERSION` 0.3.1
(commit `aba06a8`) plus the uncommitted fixes listed in §3, on the development servers (SPA 127.0.0.1:4300, API 5100,
database `lis` on the private PostgreSQL 5433). Tester: **automated dry run** (browser automation driving the client
portal exactly as a tester would; data entered through the pages, API calls only where a script says "forced").
Date: 2026-10-10. Only the **critical** scripts of the two personas were executed, in the document's order, with the
Super Admin, Accounts and Cashier personas replaced by the seeded accounts where a precondition needed them.

Deviations from a human session, all recorded below where they matter:

- The tenant parameters `autoPrintLabels`, `autoPrintJobOrder` and `autoPrintReceipt` were switched **off** through
  `PUT /api/v1/settings` before the reception scripts (the native print dialog blocks an automated browser). Printing
  (labels, job order, receipt reprint) was therefore **not exercised**; the job-order *page* and the labels/samples
  dialogs were.
- One browser profile only: the "second profile" steps (BR-17 live permission change, branch selection of a two-branch
  user, the clerk's fresh profile) were replaced by sign-out/sign-in cycles or recorded as blocked.
- Data minimisation: only the roles and users the executed scripts need were created (Reception, Technician;
  `uat.reception`, `uat.tech`), plus the catalogue items of UAT-ADM-08 and three precondition records that belong to
  scripts outside this run (doctor DR01 and preparation FAST of UAT-ADM-10, payer AXA / tier Gold of UAT-FIN-01).
- The clerk was approved on MAIN-CASH by `lab.admin.manager` (UAT-ADM-07 run with the clerk's request instead of the
  cashier's); `lab.admin`'s approval TRQ-2026-00001 was revoked and re-granted as TRQ-2026-00004 by the same script.
